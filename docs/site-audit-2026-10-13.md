# Проверка сайта — 13 октября 2026

Проверены код интерфейса, маршруты API, модели Prisma и связанные сценарии студента, преподавателя и администратора. Исправления находятся в рабочем дереве проекта. Эта проверка подтверждает перечисленные сценарии, но не гарантирует отсутствие любых ошибок при любых данных и нагрузке.

## Архитектура

| Слой | Назначение и связи |
| --- | --- |
| `frontend` | React 19 + TypeScript + Vite. Zustand хранит состояние пользователя, Axios добавляет access token и обновляет его через refresh cookie. В разработке `/api` проксируется на Python. |
| `python_backend/app/routers` | FastAPI: авторизация, роли, валидация запросов и маршруты всех разделов. |
| `python_backend/app/services` | Предметы, группы, лекции, попытки тестов, аналитика, достижения, сообщения, расписание и AI-сценарии. |
| `python_backend/schema.prisma` | PostgreSQL: пользователи, профили, группы, предметы, темы, тесты, ответы, прогресс, расписание, достижения. Заметки, задачи, карточки, викторины и разговоры хранятся как типизированные JSON-документы в `AIInteraction`. |
| `gemini_service.py` | Общий клиент Gemini. Используется чатом, домашними заданиями, подготовкой, терминами, генерацией тестов/карточек/викторин, лекциями, Фейнманом и дебатами. |
| `lecture_material.py` | Чтение локальных вложений, проверка пути и размера, извлечение DOCX/PPTX/TXT; передача PDF/изображений провайдеру. |
| `python_backend/uploads` | Файлы. Скачивание теперь проходит через авторизацию и проверку доступа к лекции. |
| `room-finder-java` | Отдельный HTTP → TCP мост поиска кабинетов; Python обращается к `/api/bridge`. |
| `mock-cpp-room-server` | Только локальный тестовый ответчик. Его ответы не подтверждают свободные аудитории или состояние камер. |
| `camera-service` | Отдельный C++ каркас; текущий сайт его не вызывает. Интеграция с физическим оборудованием отсутствует. |

Рабочая локальная схема: Vite `5173` → FastAPI `4000` → PostgreSQL `5433/aitutor`. Prisma Studio использует ту же PostgreSQL. Docker и локальный запуск описаны в README. Секреты здесь не приводятся.

## Исправленные проблемы

- Регистрация: подключение к правильной локальной БД, нормализация email/имён, ограничения bcrypt, конфликт повторной регистрации, атомарное создание профиля и токенов. Вход и изменение профиля возвращают группу студента.
- Сессии: обновление токена работает и для `/auth/me`; refresh-токен потребляется атомарно. Одновременные запросы не создают две новые сессии, сбой записи не теряет прежний токен.
- Администрирование: предмет без преподавателя, дубликаты предметов/групп/email, проверка действующего преподавателя, создание профиля студента без группы, запись аудита изменений пользователя. Защита от отключения собственного/последнего администратора. Интерфейс загружает пользователей за пределами первой сотни.
- Доступ: приватные лекции и их файлы доступны только соответствующей группе/преподавателям/администратору. Преподаватель не может публиковать по чужому предмету, назначать студентов в чужую группу или открывать чужую карточку студента.
- Группы: удаление группы с материалами/расписанием возвращает понятный конфликт; не происходит частичного удаления связей студентов. В списке преподавателя видны студенты без завершённых тестов.
- Лекции: прикреплённый материал действительно передаётся в объяснение и генерацию теста; добавлено извлечение текста. Поддерживаются лекции без текста при наличии файла. DOCX/PPTX определяются по содержимому; слайды читаются в порядке номеров. Невалидные пути, отсутствующие/пустые/слишком большие файлы возвращают понятные ошибки. Старый бинарный PPT требует преобразования в PPTX/PDF.
- Интерфейс лекций: студент может открыть общую страницу `/lectures/:id` и скачать файл с авторизацией. Сгенерированный тест открывается в проигрывателе. Поле выбора файла очищается после сохранения.
- Тесты: восстановление ответов, позиции и времени; автосохранение не откладывается при каждом ответе; время последнего вопроса учитывается. Одновременный старт возвращает одну попытку. Повторная отправка не удваивает XP. Ответы, прогресс и награды сохраняются транзакционно. Чужие/повторяющиеся вопросы отклоняются, пропущенные ответы учитываются. Завершённая попытка не принимает автосохранение.
- AI-анализ результата: проверяется завершение и владелец попытки; результат корректно сохраняется в JSON, повторно используется и отображается интерфейсом.
- Достижения: добавлено фактическое начисление по условиям каталога и однократная выдача XP. Серия занятий использует календарный день в школьном часовом поясе, включая переход через полночь в Алматы.
- Сообщения: проверка получателя и пустого текста, правильный статус прочтения, защита интерфейса от поздних ответов при смене контакта и поиска. Опрос истории не удаляет из интерфейса только что отправленное сообщение.
- Фейнман/дебаты: поиск сохранённой сессии не ограничен последними 50 записями; защита от перезаписи параллельным запросом; исправлено повышение сложности. URL сохраняет идентификатор разговора для перезагрузки страницы. При ошибке отправки текст возвращается в поле ввода.
- Ошибки интерфейса: история, аналитика, предметы, повторение, достижения, результаты, расписание и панель преподавателя показывают ошибку и повторную загрузку вместо ложного пустого состояния/падения.
- Инструменты: `npm run lint` теперь имеет зависимости и конфигурацию. Исправлены найденные ошибки, удалены неиспользуемые импорты. Обновлены совместимые версии Axios и source-map-js; итоговый `npm audit` не сообщил уязвимостей.

## Дополнительная проверка связанных действий

- Расписание студента без явного фильтра теперь относится к его группе. Студент без группы видит объяснение, а не занятия всех групп. Явный просмотр расписания другой группы через API сохранён.
- Кнопка «Повторить» передаёт конкретную тему в генератор тестов.
- Если тест уже создан, но запуск попытки дал ошибку, повторная кнопка открывает готовый тест без повторного расходования запроса генерации.
- Кнопка «Разобрать ошибки с AI» открывает чат с редактируемым запросом, содержащим реальные вопросы, ответы и результат. Сообщение отправляется после действия пользователя.
- Генератор проверяет количество и тип вопросов, непустые/уникальные варианты и наличие правильного ответа среди них. Несуществующий или отключённый предмет возвращает 404 до обращения к AI.
- Смешанный тест сохраняет отдельную тему для каждого вопроса. Темы и тест записываются одной транзакцией; параллельная генерация не дублирует темы.
- Обзор преподавателя учитывает назначенных студентов, даже когда они ещё не проходили тесты. Список, подробности и сводная статистика используют согласованный доступ по группам; карточки предметов получают код и описание.

## Дополнительные исправления перед развёртыванием

- Nginx принимает файлы до лимита backend (12 МиБ плюс multipart-заголовки) и ждёт длительные AI-запросы. Старая конфигурация возвращала 413 для файла 2 МиБ и 504 для запроса длительностью 65 секунд; новая возвращает 200 в обоих воспроизводимых сценариях.
- Access- и refresh-токены имеют разные назначения. Refresh-токен больше нельзя использовать вместо Bearer access-токена, даже при общем секрете подписи. Сохранённые старые refresh-токены принимаются для плавного обновления сессий.
- `/health` проверяет доступность PostgreSQL с ограничением времени; недоступная БД возвращает 503 вместо ложного успешного статуса.
- Завершение отклонённой/брошенной попытки запрещено. Одновременное назначение одного студента разными преподавателями сериализовано: выигрывает один запрос, второй получает 409. Отключённые студенты исключены из списка назначения.
- Смена группы преподавателем защищена от запоздалого ответа предыдущей группы; список лекций отменяет предыдущий запрос. Ошибка буфера обмена отображается корректно, добавление студента обновляет список и счётчики.

Интеграционные тесты дополнительно проходят чат и продолжение разговора, карточки, все три типа вопросов викторины, права владельца, аналитику, сообщения, расписание, откат транзакций и конкурирующие запросы. Ответы Gemini в этих тестах заменены предсказуемыми данными; настоящая PostgreSQL используется без подмены.

Для повторения Python-проверки нужна **отдельная пустая тестовая БД** с именем, начинающимся на `schedule_test_`: тесты расписания проверяют очистку всей таблицы. Нельзя запускать их на пользовательской БД. Сначала применить `python_backend/schema.prisma`, затем:

```sh
RUN_DB_TESTS=1 RUN_SCHEDULE_DB_TESTS=1 DATABASE_URL='<URL отдельной тестовой БД>' \
  PYTHONPATH=python_backend .venv/bin/python -m unittest discover -s python_backend/tests
```

Для UI-проверок использовались отдельная БД с демоданными и сервисы на `4100/5174`. Пользовательская БД не очищалась и не заполнялась тестовыми пользователями.

## Внешние ограничения

1. Gemini: при живых запросах провайдер возвращал в том числе 503 и 429 (квота). Приложение сообщает эти ошибки, но исправление кода не увеличивает квоту ключа. Для стабильной живой генерации нужен ключ с доступной квотой. Отклонённые провайдером вложения не выдаются за успешное объяснение.
2. Поиск аудиторий: текущая локальная настройка указывает на `127.0.0.1:3333`; для реального поиска должен работать Java-мост и настоящий C++ сервер. Проверенный mock не подключался вместо реального сервиса к пользовательскому сайту. Камеры и занятость реальных помещений не проверялись.
3. Production Docker-образы и nginx проверены локально. Развёртывание на удалённой VM, нагрузочные испытания и физическое оборудование этим не подтверждаются. Предупреждение о размере JS-файла относится к оптимизации загрузки.
