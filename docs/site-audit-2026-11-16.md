## Структура проекта

Текущее разделение React → FastAPI routers/services/schemas → Prisma/PostgreSQL соответствует размеру проекта. Java-мост и camera-service имеют отдельные границы и проверки. Перенос каталогов или смена стека сейчас добавили бы риск без подтверждённой пользы.

В этом изменении выделены небольшие самостоятельные части: политика CORS, общие ограничения AI-оценок и работа с локальным черновиком попытки. Добавлены повторяемые сценарии QA; изменения не требуют миграции БД.

Оставшиеся направления улучшения:

1. `AdminDashboardPage` и `TeacherDashboardPage` можно разделить по вкладкам; общую загрузку списков и повторные формы стоит унифицировать после фиксации их контрактов тестами.
2. Companion/Feynman/Debate хранят документы в JSON-поле `AIInteraction`. Для дальнейшего развития полезны версия формата и проверка старых документов при чтении. Перенос в отдельные таблицы требует спланированной миграции.
3. Несколько статистических обработчиков читают все записи пользователя, а списки Companion ограничены 100 последними элементами. При росте данных нужны серверные агрегаты, пагинация и измерение запросов на реальном объёме.
4. Production build предупреждает о крупных чанках: основной около 749 КБ, hardware около 622 КБ до gzip. Нужны измерения времени загрузки и адресное разделение; переписывать рабочую 3D-сцену ради самого предупреждения не требуется.
5. Большой `frontend/public/pc-lab-assets/lab.js` остаётся отдельным учебным движком. Его дальнейшее выделение в модули стоит сопровождать существующими 38/61 сценариями.

## Как повторить

Из корня проекта, с установленными зависимостями Python/frontend, PostgreSQL, Maven/JDK и CMake:

```sh
# Настройте DATABASE_URL на отдельную одноразовую базу schedule_test_*.
# Не используйте рабочую БД: тест расписания очищает её расписание целиком.
.venv/bin/python -m prisma db push --schema python_backend/schema.prisma --skip-generate
RUN_DB_TESTS=1 RUN_SCHEDULE_DB_TESTS=1 PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=python_backend .venv/bin/python -m unittest discover -s python_backend/tests -v
(cd frontend && npm run lint && npm run build && npm audit --omit=dev)
(cd room-finder-java && mvn test)
cmake -S camera-service -B /tmp/aituto-camera-check -DCAMERA_WITH_OPENCV=OFF -DCMAKE_BUILD_TYPE=Release
cmake --build /tmp/aituto-camera-check -j 4
ctest --test-dir /tmp/aituto-camera-check --output-on-failure
```

Для полного браузерного прохода после тестов заново заполните **ту же одноразовую БД** демоданными и запустите отдельные процессы:

```sh
PYTHONPATH=python_backend .venv/bin/python python_backend/scripts/seed.py --demo
PYTHONPATH=python_backend .venv/bin/python python_backend/tests/browser_fixture_server.py
# Во втором терминале:
(cd frontend && BACKEND_URL=http://127.0.0.1:4000 npm run dev -- --host 127.0.0.1)
# В третьем терминале, с установленным Playwright и его Chromium:
SITE_TEST_FIXTURES=1 SITE_TEST_URL=http://127.0.0.1:5173 node scripts/check-site.cjs
UI_TEST_URL=http://127.0.0.1:5173 node scripts/check-ui-regressions.cjs
LAB_TEST_URL=http://127.0.0.1:5173 node scripts/check-pc-lab.cjs
LAB_TEST_URL=http://127.0.0.1:5173 node scripts/check-pc-hardware.cjs
```

Скрипты используют `require('playwright')`; если библиотека установлена отдельно, задайте `PLAYWRIGHT_MODULE` полным путём к ней. `browser_fixture_server.py` отказывается запускаться на базе без префикса `schedule_test`; он использует настоящие сервисы приложения/БД, но подменяет HTTP-транспорт Gemini и отключает внешний поиск кабинетов. `check-site.cjs` дополнительно требует локальный URL и `SITE_TEST_FIXTURES=1`. Этот сервер предназначен только для QA, после проверки его нужно остановить.

## Границы проверки и эксплуатация

- Полное развёртывание контейнеров не выполнялось: Docker daemon в окружении недоступен. Проверены конфигурации Compose, локальная production-сборка frontend и сборка C++.
- Реальный Microsoft SQL Server, внешний C++-движок поиска и физические камеры не подключались. Их контракты проверены имитаторами/локальными тестами; работоспособность с оборудованием требует отдельного прохода.
- Основные AI-сценарии проверены с контролируемым ответом провайдера, а настоящий Gemini — одним коротким успешным запросом. Это не оценка качества всех генерируемых материалов или устойчивости квот.
- При `NODE_ENV=production` задайте случайные `JWT_SECRET` и `REFRESH_TOKEN_SECRET` длиной от 32 символов и точные `CORS_ORIGIN`. Старые development/примерные ключи теперь намеренно не позволяют запускать production.
- API управления пользователями шире текущего UI администратора: часть операций изменения роли/активности проверяется через API. Новые административные формы в рамках исправления ошибок не добавлялись.
- Нагрузочный тест, внешний pentest, Safari/Firefox и полный аудит advisories Python/Java-зависимостей не выполнялись. Production npm-зависимости проверены `npm audit`.
