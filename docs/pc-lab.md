# Практикум ПК и Windows

## Интеграция

Маршрут `/pc-lab` доступен гостям и зарегистрированным пользователям. Ссылки находятся на главной странице и в боковом меню; карточки результатов — в обзоре и профиле.

React-оболочка в `frontend/src/features/pc-lab/` отвечает за авторизацию, локальный черновик, запросы API, баллы и статус синхронизации. Стенд находится в `frontend/public/pc-lab-assets/` как отдельные HTML/CSS/JS в same-origin iframe. Это сохраняет исходные SVG и обработчики готового HTML, полностью изолируя его CSS от сайта. Фрейм не получает токен авторизации. Обе стороны проверяют `origin` и `source` сообщений; входящий прогресс нормализуется по разрешённым значениям.

Каталог ресурсов отличается от маршрута React, чтобы Nginx не перенаправлял `/pc-lab` на статический `index.html`. Нехешированные ресурсы стенда имеют `Cache-Control: no-cache`; сборочные хешированные JS/CSS сайта продолжают кешироваться.

## Функции и исправления

- Восемь отдельных моделей, три слоя, рентген и учёт уникальных разобранных узлов.
- Общий стенд и разборка; инспектор показывает фактическую версию BIOS и состояние ОС.
- Восемь устанавливаемых элементов, проверки зависимостей и разъёмов, подсказка, автошаг и повторная попытка. Слот выбранной детали поднимается над соседними областями клика: область кулера больше не блокирует SSD. Enter/Space доступны для установки. Изменения от SVG-кликов сохраняются даже при `stopPropagation`.
- BIOS: POST/DEL, UEFI, M-Flash, выбор ROM, запись SPI и v2.40. Повторный запуск сбрасывает завершение.
- Windows: TPM/Secure Boot (два решения), Intel VMD (два решения), MBR/GPT, OOBE; три редакции, язык/регион/клавиатура, размеры C/D, три обязательных драйвера, рабочий стол и итоговая конфигурация.
- Переключение вкладок сохраняет сборку и останавливает активные таймеры. Прерванную запись BIOS/Windows можно запустить снова. Завершённые этапы восстанавливаются после перезагрузки.
- Выключенный чекбокс неисправности не считается её решением. Повторное включение неисправности возвращает установщик на соответствующий этап и снимает ранее полученную отметку этой неисправности.
- Панель установщика размещена под рисунком и не закрывает аппаратные компоненты. Адаптивные сетки, focus-индикаторы, reduced-motion, остановка CSS-анимаций при скрытии вкладки.

Команды выполняются только в симуляции. Оценка предназначена для самостоятельной практики, не для защищённого экзамена: сервер проверяет данные и вычисляет баллы, но события практикума сообщает браузер. Исходный вымышленный код TPM заменён явно учебным `LAB-TPM`. Старые сценарии LabConfig/OOBE BYPASSNRO помечены как зависящие от версии установщика, со ссылками Microsoft. Для DiskPart объяснено действие `clean` на настоящем диске.

## API и хранение

- `GET /api/v1/pc-lab/progress` — сохранение текущего пользователя или нулевой результат.
- `POST /api/v1/pc-lab/progress` — частичное обновление, серверный расчёт оценки и новая ревизия.
- Таблица `pc_lab_progress`: уникальная связь с User, каскадное удаление, разобранные модели, сборка/ошибки, BIOS, Windows, решённые неисправности, раздел C, состояние возобновления, ревизия и даты.
- Неверные значения и лишние поля отклоняются. Пользователь не передаёт чужой ID или готовый балл.
- При отправке клиент передаёт `revision`. Транзакционная блокировка строки пользователя сериализует одновременные записи; устаревшая ревизия получает 409. UI предлагает явно заменить локальный черновик серверной версией.
- Автосохранение с задержкой 350 мс. До ответа сервера изменения остаются в localStorage; ошибки сети не уничтожают черновик. Есть повторное подключение. Гостевой ключ и ключи пользователей раздельные: результаты чужой сессии не импортируются автоматически.

Оценка: `floor(15 × число_разобранных / 8)` + сборка `max(15, 30 − 2 × ошибки)` при завершении + BIOS 20 + Windows 35 при завершении и решении всех четырёх неисправностей. Зачтено от 80. `completed_at` появляется только при завершении всех четырёх разделов практикума.

## Проверки

- `npm run build --prefix frontend` — TypeScript и Vite. Сохраняется предупреждение Vite о размере существующего общего bundle; модуль практикума загружается лениво.
- `npm run lint --prefix frontend` — без ошибок и предупреждений.
- 67 Python-тестов, включая новые проверки оценки, авторизации, изоляции пользователей, частичного сохранения, валидации, конкурентной записи и каскадного удаления. Запускать с `RUN_DB_TESTS=1 RUN_SCHEDULE_DB_TESTS=1` только на отдельной тестовой БД `schedule_test_*`.
- `scripts/check-pc-lab.cjs` — 33 браузерные проверки через UI. Требует Playwright (`PLAYWRIGHT_MODULE` при внешней установке), API и Vite с отдельной тестовой БД. По умолчанию `http://localhost:5174`; внешние адреса запрещены. Временная учётная запись остаётся только в этой удаляемой тестовой БД.
- Визуально проверены desktop, мобильные 390/320 px и снимки SVG с плотностью 4×. Геометрия сверена с предоставленным HTML.

## Обновление базы и откат

Для существующей установки сначала сделать резервную копию PostgreSQL, uploads и серверной конфигурации. Собрать новые backend/frontend, затем один раз применить `python_backend/migrations/20261015_pc_lab_progress.sql` через `psql -v ON_ERROR_STOP=1`, после чего обновить контейнеры. Миграция транзакционная, только добавляет таблицу и не изменяет существующие данные. На новой локальной тестовой БД допустим `prisma db push`.

Не применять `--accept-data-loss` и не сбрасывать базу. При откате вернуть предыдущие образы приложения; новую таблицу можно оставить, старому приложению она не мешает. Повторный запуск SQL на уже мигрированной БД намеренно завершится ошибкой вместо скрытого изменения схемы.
